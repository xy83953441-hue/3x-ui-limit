# 安装时自动配置 HTTPS

安装过程中，在证书方式选择处按回车或选择 `2`，使用服务器公网 IPv4 申请 Let's Encrypt IP 证书，无需自有域名。IPv6 为可选项；只填写确实属于该服务器且公网可达的地址。

自动流程会：

- 检查 TCP 80 是否被占用以及 socat 是否可用，不会停止占用端口的其他应用。
- 启动并启用 cron/crond，安装并检查 acme.sh 的续期任务。
- 在运行中的 firewalld（公网出口网卡所属区域）或 UFW 中放行 TCP 80。保留永久规则供后续续期，不关闭防火墙、不全局重载规则。
- 申请约 6 天有效的 IP 证书，设置 3 天续期间隔；不强制反复签发，未到期时复用已有证书。
- 检查证书是否过期、证书与私钥是否匹配，成功写入面板后才报告配置成功。
- 根据实际配置生成访问地址；成功配置 HTTPS 后放行面板端口，通常仍使用安装时选择的端口，无需改成 443。

## 必要条件与边界

公网 TCP 80 必须能到达本机，且以后续期时仍然可用。云平台安全组、上游防火墙和 NAT 转发无法由本机安装脚本自动处理。放行本机端口不代表公网一定可达。

首次运行仍需回答安装向导的问题；这是证书步骤自动完成，不是整个安装过程完全无人值守。

若没有运行中的 firewalld/UFW，脚本会提示人工检查其他防火墙，不会擅自覆盖 iptables/nftables 规则。

## 排错

IP 证书申请日志保存在 `/var/log/x-ui/acme-ip.log`（权限 600）。失败后保留原有证书和 ACME 账户，不循环强制申请，不把失败报告为 HTTPS 成功。日志可能包含网络及账户信息，分享前请检查。

面板启动失败时，systemd 系统可执行 `journalctl -u x-ui -n 50 --no-pager`。

这个修改针对新安装或再次执行安装向导，不会自动修改已经运行的服务器，也不替换 `x-ui` 菜单第 19 项的独立证书流程。已有面板不要为了申请证书直接重装。

## 验证

运行 `bash tests/install_ssl_test.sh` 可执行隔离测试，包括端口检查、证书与私钥匹配、防火墙区域、cron 服务选择及签发/安装/配置失败分支。测试模拟外部命令，不申请真实证书、不修改真实防火墙。

本地已通过 Bash 语法检查及隔离测试；真实 Linux 安装、公开网络验证和跨天自动续期仍需在测试服务器验证。
